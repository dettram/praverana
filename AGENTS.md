# AGENTS.md — правила работы с этим репозиторием

## Главное правило

**Нашёл — заводи issue сразу.** Любая находка: баг, сомнительное поведение, нехватка функции,
неясный текст, дыра в тестах, отсутствующая норма, долг в дизайне — становится задачей в
`dettram/praverana` в тот же момент, а не «потом запишу». Ничего не держим в голове и в чате.

Что считается находкой:

- воспроизводимая ошибка (проверка пропускает дефект, отчёт падает, разметка ломает файл);
- место, где интерфейс заставляет догадываться или врёт числом;
- нарушение канона (`docs/SYSTEM.md`, `docs/DESIGN.md`) — цвет, кегль, компонент;
- пробел в нормативной базе (нормы нет в фонде, пункт не находится);
- отсутствие проверки, теста, состояния (пусто/загрузка/ошибка);
- расхождение документации и кода.

## Как заводить

```powershell
# короткий путь: заголовок, тело из файла, метки
powershell -ExecutionPolicy Bypass -File tools/new-issue.ps1 -Title "Поле поиска не получает Onest" `
    -BodyFile "$env:TEMP\body.md" -Labels "ui,bug"
```

Или `gh issue create --title "…" --body-file <файл> --label "…"`.

Требования к issue:

1. **Заголовок** — что не так, без «улучшить» и «оптимизировать».
2. **Тело** — три блока: что происходит, как повторить, что считаем правильным.
3. **Ссылки на код** — `файл:строка`, чтобы не искать заново.
4. **Метки** — минимум одна из: `bug`, `enhancement`, `norms`, `report`, `ui`, `landing`,
   `accessibility`, `corpus`, `documentation`.
5. **Проверка** — чем закроем: демо-проект, гейт, скриншот до/после, тест.

## Закрытие

- Один PR — одна issue; в коммите `(#N)`.
- Закрываем только с проверкой: `app/engine.py` на `samples/demo-project`, гейты лендинга,
  скриншоты для UI.
- Если находка оказалась неверной — закрываем с причиной, а не удаляем.

## Что не публикуем

Тексты ТНПА, проектную документацию заказчиков, персональные данные. См. `CONTRIBUTING.md`.
