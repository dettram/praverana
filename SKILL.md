# Аудит строительных расчётов (РБ, база 18.11.2026)

Скилл соединяет три вещи, которых у модели нет «из головы»:

1. **Нормативный корпус** `~/Desktop/Нормы-Беларусь-2026` — реестр, полные тексты, чек-листы,
   методика аудита 14 объектов. Нормы читаются из корпуса, а не вспоминаются.
2. **Детерминированные скрипты** — индексация корпуса, проверка ссылок по реестру, реестр чисел,
   арифметика, минимальные классы бетона. Модель не считает в уме.
3. **Протокол аудита** — семь ролей (A–G), оценка 0–10, формат отчёта, запреты
   (`references/audit-protocol.md`).

> **Главное правило.** Любое число в отчёте либо взято из файла с `файл:строка`, либо посчитано
> скриптом, либо помечено «не проверено». Третьего не дано.

## Когда применять

- проверить расчётную часть проекта (КР/КЖ/КМ): нагрузки, сочетания, класс бетона, защитный слой,
  армирование, стали и соединения;
- проверить нормативные ссылки: существует ли шифр с таким годом, действует ли, чем заменён;
- собрать реестр чисел документа и найти внутренние противоречия и арифметические ошибки;
- проверить сметные объёмы и удельные показатели на сходимость;
- проверить данные Revit/IFC-модели против спецификаций и ведомостей.

Не применять: для расчёта «с нуля» (это `structural-engineering` + СП 5.03.01/5.04.01),
для юридической экспертизы, для подписания чужого расчёта.

## Рабочий процесс

Все команды — из корня скилла. Зависимости ставит `uv`, Python — managed.

```powershell
cd $env:USERPROFILE\.config\opencode\skill\stroy-calc-audit
```

### 1. Индекс корпуса (один раз, потом по обновлению)

```powershell
uv run --with pypdf --with python-docx --with openpyxl --with fonttools scripts/build_index.py
```

Строит SQLite + FTS5 в `~/.stroy-audit/index.sqlite`: документ → страница → фрагмент, с шифром
нормы из имени файла. Сканы без текстового слоя попадают в отчёт как `no_text`, PDF с паролем —
как `locked`, ошибки чтения — в `errors`. Ничего не пропадает молча.
Сводка: `uv run scripts/index_stats.py`.

### 2. Поиск пункта нормы (для каждой ссылки в отчёте)

```powershell
uv run --with snowballstemmer scripts/search.py --query "защитный слой бетона" --code "СП 5.03.01-2020" --limit 5
```

Морфология: при наличии `chunks_stem` (строится `build_stems.py`) поиск идёт по стеммированному
индексу — «нагрузка» находит «нагрузки». Флаг `--no-stem` отключает.
В консоли с cp1251 русский запрос передаётся файлом (`--query-file q.txt`, UTF-8), результат —
через `--out s.txt`. Выдаёт `файл:страница` и фрагмент; цитировать в отчёте можно только это.

### 3. Проверка нормативных ссылок объекта

```powershell
uv run scripts/norm_check.py --path ".\объект" --out ".stroy-audit\P000\norms.md"
```

Классифицирует каждую ссылку: действует / не в реестре / отменена с заменой / СНиП /
без года. Статусы — основной реестр корпуса плюс `data/registry-extra.csv` (проверено 20.11.2026).
Код возврата 1 при блокерах — годится для гейта.

### 4. Реестр чисел и арифметика

```powershell
uv run --with pypdf --with python-docx scripts/numbers_ledger.py --path ".\объект\КР.md" --out ".stroy-audit\P000"
```

Пишет `ledger.csv`, `ledger.md`, `issues.md`: все числа с единицами и `файл:строка`,
проверенные выражения `a × b = c`, противоречия «одна величина — разные значения», смешение единиц.

### 5. Точечные проверки

```powershell
uv run scripts/checks.py concrete --exposure XC3 --class C25/30
uv run scripts/checks.py rebar --d 12 --n 4
```

### 5a. Проверка цитаты: существует ли пункт

```powershell
uv run scripts/clause.py --code "СП 5.03.01-2020" --clause 6.3.4.1
uv run scripts/clause.py --text ".\объект\ПЗ.md"
```

Ищет пункт в проиндексированном тексте именно этой нормы и даёт `файл:страница`.
Режим `--text` вытаскивает из документа все связки «шифр + п./табл./прил.» и проверяет
каждую: `OK` или `НЕТ — не найдено в корпусе`. Это отсекает ссылки на несуществующие пункты.
Пакетная проверка отчётов: `uv run scripts/cite_audit.py --out cite-audit.md` — делит
неподтверждённые на «нет текста нормы» и «пункта нет в тексте».

### 6. Отчёт

Собирается по `references/audit-protocol.md` (разделы 1–7, оценка 0–10). Артефакты — в
`.stroy-audit/<объект>/`, исходники не правятся.

### 7. Массовое пополнение реестра

```powershell
uv run --with pypdf scripts/harvest_registry.py `
  --stn-json stn-splist.json --minskgsn-html minskgsn-sn.html `
  --mchs-pdf mchs.pdf --minenergo-html minenergo.html `
  --min-hits 3 --write --report harvest.md
```

Слияние источников: `data/registry-extra.csv` → реестр СН и СП (stn.by) → даты введения
(minskgsn.by) → ТКП МЧС → ТКП Минэнерго → коды из проектных текстов (≥ 3 упоминаний).
Курируемые строки реестра не перезаписываются, перед записью делается `.backup-ГГГГММДД.csv`.
Итог на 20.11.2026: 358 записей (СН 79, СП 118, ТКП 57, ГОСТ 56, СТБ 39).

### 8. Приём PDF нормы в корпус

```powershell
uv run --with pypdf scripts/ingest_pdf.py --spec ingest.json --update-registry
```

`ingest.json` — список `{file, code, title, source}`. Скрипт: копирует в
`<корпус>/_inbox-ГГГГММДД/<вид>/<ШИФР> — <название>.pdf`, проверяет сигнатуру PDF,
страницы, текстовый слой и наличие шифра в тексте, пишет `manifest.csv` (SHA-256, вердикт)
и дописывает в реестр пометку `PDF: …`. Вердикты: `verified` / `no_text` / `mismatch` /
`not_pdf` / `unreadable`. После приёма — `build_index.py --append --only "_inbox-…"`.

Каких норм нет файлом: `uv run scripts/pdf_gaps.py --out gaps.csv`.

### 9. Обслуживание индекса

```powershell
uv run scripts/build_clauses.py                                  # норма → пункт → заголовок → страница
uv run --with snowballstemmer scripts/build_stems.py             # морфологический поиск
uv run --with pymupdf --with rapidocr-onnxruntime --with pillow scripts/ocr_batch.py   # OCR сканов
```

`build_clauses.py` даёт таблицу `clauses` (44 тыс. пунктов): `clause.py` отвечает
«пункт есть, заголовок, страница» без перебора текста. `build_stems.py` строит `chunks_stem`.
`ocr_batch.py` пишет sidecar `<имя>.ocr.txt` рядом со сканом — после него нужен пересбор индекса.

OCR: tesseract 5.5.4 с языком `rus` установлен в `%USERPROFILE%\tess` (conda-среда через
micromamba), данные — в `tess\Library\share\tessdata`. Переменные `TESSERACT_CMD` и
`TESSDATA_PREFIX` скрипт подставляет сам. Движки: `--engine tess|easy|rapid`.
Tesseract даёт заметно лучшее качество на старых сканах, чем easyocr.

### 10. ПОС и ППР (СН 1.03.04-2020)

```powershell
# скелет по составу нормы
uv run --with python-docx scripts/make_pos_ppr.py --kind pos --object "P324" --out pos.docx
# проверка комплектности (код 1 при пропусках)
uv run --with python-docx scripts/check_pos_ppr.py --kind ppr --path ppr.docx
# перечень ТНПА из реестра (140 документов, 25 групп) -> data/norms-pos.json|md
uv run scripts/build_norms_list.py
# лист СГП А1 М 1:500 (PDF + PNG) -> <проект>\docs\ПОС-ППР\СГП
uv run --with matplotlib python scripts/make_sgp_sheet.py --out-dir "<проект>\docs\ПОС-ППР\СГП"
# ППР на монтаж металла (прил. В.2), массы считаются в скрипте
uv run --with python-docx python scripts/make_ppr_metal.py --out-dir "<проект>\docs\ПОС-ППР"
# заполненный черновик по данным объекта (пример — 2026-АТЛ)
uv run --with python-docx scripts/make_atlas_docs.py --out-dir "<проект>\docs\ПОС-ППР"
```

Состав: **В** — ППР (11 блоков), **Г** — ПОС (22 блока), `references/pos-ppr-composition.md`,
`data/pos-ppr.json`. Скелеты — `06-Справочники/Шаблоны-ПОС-ППР/`.

`make_atlas_docs.py` — образец заполненного документа (27 с. ПОС + 16 с. ППР). Структура взята
из практики проектных организаций (образец: ПОС 42-23-ПОС1, `P:\(Инв.№000)-00-00`):
1 Общая часть (основания + ТНПА + «не является основанием для производства работ») →
2 сведения об объекте и условиях (2.1 район … 2.9 условия) → 3 нормативная продолжительность →
4 организационно-технологическая схема → 5 методы работ → 6 зимнее время → 7 охрана труда →
8 пожарная → 9 экология → 10 энергоэффективность → 11 геодезический контроль → 12–14 ресурсы →
15 ТЭП → 16 СГП → 17 соответствие прил. Г → 18 допущения → 19 лист согласования →
приложение А (перечень ТНПА) → приложение Б (формы Д–П).

Оформление (обязательно): **Times New Roman во всех стилях**, тело 14 пт, интервал 1,5, отступ
1,25 см, таблицы 8–9,5 пт с повтором шапки, колонтитул «стр. X из Y», **поле TOC** для оглавления
(`<w:updateFields w:val="true"/>` — собирается при открытии; перед экспортом в PDF обновить поле,
иначе в PDF останется заглушка). Шрифт и кегль дублировать на уровне run у заголовков: Word теряет
их из стиля при пересохранении. После экспорта проверять PDF на посторонние шрифты
(`pymupdf`, `span["font"]`): в оглавлении Word подставляет Cambria для отточий — лечится
`$toc.Range.Font.Name = "Times New Roman"` перед вторым обновлением.

СГП рисуется `make_sgp_sheet.py` (matplotlib, лист А1 594 × 841 мм, 1 м = 2 мм, рамка 20/5 мм,
штамп 185 × 55, ведомость зданий, показатели, примечания, план подготовительного периода).
Вставляется в ПОС как приложение Б (PNG 150 dpi, ширина 16,5 см), рабочий лист — отдельный PDF.
Посадку зданий брать из ТЗ; при отсутствии генплана на листе обязательна оговорка
«схема условная, не является основанием для разбивки».

Перечень ТНПА в приложении А собирается из `02-Реестр.csv` с проверкой статуса и наличия файла
в индексе; норма без файла помечается «нет» — это ограничение, а не подтверждение. Генератор
предупреждает, если шифр упомянут в тексте, но отсутствует в перечне (проверка «ссылки в никуда»).

Правила, которые нельзя нарушать:
- нормативная продолжительность — только по СП 1.03.11-2023; нет файла — писать «не определено»;
- графическая часть СГП и проект крановых путей — отдельные документы, в тексте помечать «не выполнено»;
- каждое условное число — в реестр допущений с указанием, чем закрывается;
- статус документа — «черновик, не для производства работ» до подписей (п. 7.2);
- шифр нормы брать только из реестра: «СН 5.03.01-2020» не существует — правильно «СП 5.03.01-2020».


### 11. Интерфейс аудита проекта (локальный веб)

Продукт называется **Праверана.by**: `/` — лендинг, `/app` — инструмент. Палитра и орнамент —
из государственной символики (красный, зелёный, золотой, бумажный фон); герб не воспроизводится
(использование регулируется законом). Шрифты **локальные** (`@font-face`, OFL): Onest + JetBrains
Mono, `app/ui/assets/fonts/fonts.css`, без внешних запросов.

Лендинг собран на ките `design-taste-frontend` и проходит его гейт: `GATE: PASS` (2 waiver
в `app/ui/.taste-skill/waivers.json`, 8 WARN), copy-lint 0 FAIL, consistency 0 FAIL на 1440,
390 и обходе 320. Node 22 лежит в `%LOCALAPPDATA%\node22` (нет в PATH — добавлять вручную).
Повторная проверка — команды в `app/README.md`.

```powershell
cd "$env:USERPROFILE\.config\opencode\skill\stroy-calc-audit"
uv run --with fastapi --with uvicorn --with python-docx --with pypdf --with python-multipart ^
    python app/server.py      # http://127.0.0.1:8765
```

Папка проекта (по пути или drag&drop) → замечания с файлом и нормой → выгрузка DOCX/PDF
и ZIP с размеченными копиями (комментарии Word + подсветка). Под сводкой — динамика
с предыдущим прогоном и список последних прогонов. Проверки: шифры против реестра, пункты против
индекса, комплектность по именам файлов, блоки прил. Г/В для ПОС/ППР, заглушки.
Движок — `app/engine.py` (он же CLI), отчёт — `app/report.py`, разметка — `app/markdoc.py`,
история — `app/history.py`. Подробности и ограничения — `app/README.md`.

Правила, которые всплыли при сборке:
- один шифр — одна строка со списком файлов, иначе таблица тонет в повторах;
- DOCX и PDF одного документа — один источник (ключ по имени без расширения);
- пару «шифр — пункт» брать только внутри 80 знаков одной строки, иначе пункт приписывается
  чужой норме («п. 5.04.01» к «ГОСТ 24045»);
- вид документа (ПОС/ППР) определять по имени файла, а не по пути: папка `ПОС-ППР` ломает
  определение;
- в DOCX-отчёте списки делать тире, а не стилем List Bullet: тот тянет Symbol/Arial и рушит
  требование «только Times New Roman».

## Режимы

| Режим | Вход | Что проверяется | Опоры |
|---|---|---|---|
| `calc` | КР/КЖ/КМ, расчёты, ПЗ | нагрузки, сочетания, класс бетона, слой, армирование, стали, соединения | `checks-*.md`, `checks.py` |
| `norms` | любой текст проекта | шифры, годы, статусы, замены, СНиП | `02-Реестр.csv`, `norm_check.py` |
| `numbers` | отчёты, сметы, ведомости | реестр чисел, арифметика, единицы, противоречия | `numbers_ledger.py` |
| `bim` | IFC/CSV-выгрузка Revit, спецификации | сходимость объёмов и марок с ведомостями | `numbers_ledger.py`, `05-BIM` |

## Контракт результата

- Таблица нарушений: `№ | нарушение | где (файл:строка/лист) | норма (шифр + пункт) | действие`.
- Каждая норма — с годом и подтверждением статуса (реестр/карточка), иначе «не проверено».
- Оценка 0–10 по рубрике; в разделе ошибок нет слов «проверить», «вероятно», «обычно».
- Есть раздел «Ограничения аудита»: что не читалось и почему.
- Итог — 3–5 пунктов из таблицы, без новых фактов и без прогноза «после исправления соответствует».

## Ограничения и честность

- База знаний — на **18.11.2026**, дополнение проверено **20.11.2026** (`references/norm-status-by.md`,
  `data/registry-extra.csv`). Всё, что введено позже, проверяется на `pravo.by` / `minskgsn.by`;
  без проверки писать «статус не подтверждён».
- Полные тексты СН — только те, что лежат в корпусе. Если пункта нет в индексе, это
  «нет текста в корпусе», а не «норма не требует».
- `СП 5.04.01-2021` в корпусе закрыт паролем (`locked`): стальные конструкции проверяются
  по `10-Металл-ЖБ.md` и выпискам, полный пункт — только из внешнего фонда.
- Таблицы СП 5.03.01/5.04.01 в PDF могут терять вёрстку: значение из `checks.py` всегда
  сопровождается ссылкой на таблицу и требует сверки с PDF.
- Скилл не заменяет экспертизу и подпись ГИПа. Он готовит проверяемый черновик.
