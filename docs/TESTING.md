# Тесты

Стратегия для локального продукта: быстро, детерминированно, без корпуса норм и без Word.
Тесты — часть Definition of Done (`docs/GITHUB.md`), а не отдельная волна «когда-нибудь».

## 1. Принципы

1. **Детерминизм.** Один вход — один выход. Время, случайность и порядок файлов не влияют на
   результат (кроме явно нормализуемых полей).
2. **Офлайн.** Никакой сети, моделей и внешних API. Тест, который ходит в интернет, — не тест.
3. **Без корпуса.** Unit-тесты не зависят от `~/.stroy-audit` и фонда норм. Корпусные проверки —
   отдельная метка `corpus`, в CI пропускаются.
4. **Без данных заказчика.** Только `samples/demo-project`, синтетические DOCX/PDF и маленькие
   фикстуры в репозитории.
5. **Быстро.** Unit-набор — до 10 секунд; полный без UI — до минуты.
6. **Проверяем поведение, а не текст.** Точные формулировки замечаний можно менять; тест должен
   ловить «пропустил дефект», а не «слово стоит вторым».

## 2. Пирамида

| Уровень | Что | Скорость | Где |
|---|---|---|---|
| Unit | чистые функции: шифры, пары, оценка, история | мс | `tests/test_*.py` |
| Contract | FastAPI через `TestClient`, JSON-схема, коды ответов | секунды | `tests/test_server.py` |
| Integration | движок на демо-папке, DOCX/разметка, ZIP | секунды | `tests/test_demo_project.py` |
| E2E | браузер: `/app`, загрузка, таблица, выгрузки | десятки секунд | `tests/test_ui.py` (`ui`, план — #86) |
| Manual | Word→PDF, лендинг-гейт, вкус, реальный корпус | — | чек-лист PR |

## 3. Матрица по модулям

### `scripts/common.py` — цель 90%

- `norm_code`: нижний регистр, лишние пробелы, дефисы `–—−`, `*`, NFKC, «СТБ EN», «ГОСТ ISO».
- `year_of`: `-2020` → 2020, `-99` → 1999, `-20` → 2020, `-123` → None.
- `extract_citations`: несколько ссылок в строке, номер строки, контекст ≤ 240, без префикса — пусто.
- `read_text`: UTF-8, UTF-8 BOM, cp1251, битые байты → replacement.
- `clean`, `short`: пробелы/переводы строк, граница длины, многоточие.

### `scripts/norm_check.py` — цель 80%

- `classify`: СНиП → error; `CURATED_OUTDATED` → error с заменой; шифр без года (кроме ГОСТ) →
  warn; действующий → ok; «не проверен» → warn; «не вступил» → warn; «не применяется» → error;
  заменён через `replaced_by` → error; отсутствует → warn.
- `load_registry`: временный `02-Реестр.csv` + `data/registry-extra.csv`; строка с недействующим
  статусом регистрирует замену как действующую; курируемые строки не перезаписываются.
- `_close`: не подсказывает заведомо чужой шифр (cutoff).

### `app/engine.py` — цель 80%

- `pair_citations`: пара в одной строке; пункт дальше 80 знаков — не пара; «СП 5.04.01-2021» не
  считается пунктом; два шифра — пункт относится к ближайшему предшествующему; пункт из одной
  цифры отбрасывается.
- `check_completeness`: все группы найдены; регистр; `ПОС` не путается с `ППР`; пустая папка —
  одно замечание со списком.
- `check_composition`: ПОС/ППР по имени; по заголовку в первых 3000 знаках; `-КМ`/«монтаж» →
  информационное В.2; отсутствующие блоки перечислены и обрезаны до 12; оговорка «не может
  служить основанием» для ПОС.
- `check_placeholders`: жёсткие до 8 + строка «ещё N»; мягкие до 3; регистр.
- Оценка: 10 − ошибки − предупреждения − инфо, границы 6/3/1; пороги 5 и 8.
- Детерминизм: два прогона на демо → одинаковые findings после нормализации.

### `scripts/clause.py` — цель 80%

- Нет БД → пустой результат, без падения.
- Пункт есть/нет; `limit`; нормализация шифра; пункт с буквами (`6.3.4.1а`) — поведение зафиксировать.

### `app/history.py` — цель 80%

- `save`/`previous`: ключ папки, время, хеш.
- `compare`: замечание с изменившимся счётчиком — не новое; перестановка строк — не новое;
  смена состава выборки → пометка «сравнение условное».

### `app/report.py` — цель 60%

- DOCX открывается `python-docx`; A4; Normal = Times New Roman; заголовки с TNR на уровне run.
- Поле TOC (`w:updateFields`), повтор шапки таблицы, «стр. X из Y».
- Сводка: ошибки/предупреждения/инфо, оценка и её порог.
- Ограничения и список прочитанных документов присутствуют.
- PDF: `skip`, если Word/COM недоступен (CI), иначе — страница и шрифты.

### `app/markdoc.py` — цель 60%

- Комментарий ставится в копию, исходник не меняется.
- Не больше 3 вхождений на шифр и 80 комментариев на файл.
- Разрыв run и таблица; регистр; шифр, разорванный переносом, — известное ограничение.
- PDF не размечается.

### `app/server.py` — цель 70%

- `GET /`, `/app`, `/brand` → 200 и HTML.
- `POST /api/audit` с демо-папкой → job, сводка, findings.
- `POST /api/upload` с DOCX → job; пустой файл → 4xx.
- `GET /api/report/{job}.docx` → 200; неизвестный job → 404; `.pdf` без Word → понятная ошибка.
- `GET /api/marked/{job}.zip` → ZIP, структура папок.
- Path traversal (`../`, абсолютный путь) → отказ.
- Ошибка аудита → `role="alert"`-контракт на фронте (проверяется в UI-тесте).

### `tools/check-imports.py` — цель 80%

- Чистая фикстура → 0; цикл → 1; `scripts → app` (плоский и пакетный) → 1; дубль имён → 1.
- Запуск через `subprocess`, проверка кода возврата и строк.

### `tools/check-assets.py` — цель 80%

- Нет локального `src`/`href`/`url(...)` → 1; файл есть → 0.
- `../assets` из `/brand` разрешается от `app/ui`, а не от `brand/`.
- Внешние URL, анкоры, `data:` и серверные маршруты (`/app`) пропускаются.

### UI (`ui`, Playwright) — без покрытия

- Лендинг: 200, нет внешних запросов, шрифты локальные, CTA ведёт на `/app`.
- `/app`: пустое состояние, drag&drop/путь, загрузка, таблица, фильтры, динамика, выгрузки.
- Ошибка сервера → текст и `role="alert"`, без вечного бегуна.
- 1440 и 390; клавиатура: tab, enter, escape; axe — 0 critical.
- Скриншоты — в `docs/pr-assets/<N>/` по `docs/GITHUB.md`.

## 4. Фикстуры

```
tests/
  conftest.py              sys.path для app/ и scripts/, фикстура Auditor
  test_common.py           шифры, годы, цитаты, чтение файлов
  test_norm_check.py       классификация ссылок
  test_engine.py           пары, комплектность, ПОС/ППР, заглушки, оценка
  test_check_imports.py    гейт циклов на фикстурах
  fixtures/                (план) registry.csv, index.sqlite
  golden/                  (план) demo-findings.json
```

- `samples/demo-project/ПЗ-демо.docx` — основной вход; генерируется `samples/make_demo.py`.
- PDF для тестов — маленький синтетический, не скан.
- DOCX для разметки — копия демо в `tmp_path`.
- Фикстуры ≤ 100 КБ; большие файлы генерируются в тесте.

## 5. Нормализация и golden

Перед сравнением убираем: `duration_s`, абсолютные пути, `root`, время, порядок файлов.
Оставляем: категория, severity, шифр, пункт, файл (относительный), страница/фрагмент, текст
замечания без счётчиков.

Golden обновляется осознанно: diff в PR показывает, какое замечание появилось/исчезло. Массовое
обновление golden без объяснения — блокер ревью.

## 6. Покрытие

Считаем не «процент по репозиторию» — там 36 одноразовых скриптов корпуса, — а ядро:

| Модуль | Сейчас | Минимум |
|---|---|---|
| `app/engine.py` | 60% | 80% |
| `scripts/common.py` | 57% | 85% |
| `scripts/norm_check.py` | 47% | 80% |
| `scripts/clause.py` | 19% | 80% |
| `app/history.py` | 0% | 80% |
| `app/server.py` | 0% | 70% |
| `app/report.py`, `markdoc.py` | 0% | 60% |
| `tools/check-imports.py` | поведенческие тесты | — |
| `tools/check-assets.py` | поведенческие тесты | — |
| **Ядро (первые пять)** | **≈46%** | **75%** |
| Одноразовые `scripts/` (`build_*`, `make_*`, `harvest`, `ocr`) | не считаем | — |

Новое правило без теста не принимается. Снижение покрытия ядра — блокер, кроме случая удалённого
мёртвого кода с объяснением. Общий процент по репозиторию не KPI: скрипты корпуса требуют фонда
и запускаются вручную.

«Сейчас» — на 25.11.2026, после первого набора: 59 тестов, 0.9 с.

## 7. Команды

```powershell
# весь набор
uv run --with-requirements requirements-dev.txt python -m pytest -q

# только быстрое, без UI и корпуса
uv run --with-requirements requirements-dev.txt python -m pytest -q `
    -m "not ui and not corpus and not slow"

# покрытие
uv run --with-requirements requirements-dev.txt python -m pytest -q `
    --cov=app --cov=scripts --cov-report=term-missing
```

Зависимости разработки — `requirements-dev.txt` (pytest, pytest-cov, httpx, python-docx,
pypdf; Playwright — по желанию, отдельной группой). Версии фиксируются.

## 8. Метки pytest

| Метка | Что | CI |
|---|---|---|
| `slow` | производительность, большие папки | пропуск |
| `corpus` | нужен фонд норм/индекс | пропуск |
| `ui` | Playwright, браузер | отдельный job |
| `windows` | Word COM, PDF | только Windows локально |

Тест без метки обязан работать в CI на Ubuntu без корпуса и Word.

## 10. Баг → тест

1. Воспроизвести на демо или синтетике.
2. Написать падающий тест; убедиться, что он падает именно по причине бага.
3. Исправить; тест зелёный; старые тесты не сломаны.
4. Добавить фикстуру, если нужен новый вид входа.
5. В PR — ссылка на issue и строка «тест падал до, проходит после».

Баг без регрессионного теста не закрывается. Если тест невозможен (Word COM, реальный корпус) —
ручной чек-лист и скриншот/PDF в PR.

## 11. Производительность и безопасность

- Генерируем 600 файлов и PDF на 80 страниц; замеряем, не роняем CI. Цель — не деградировать
  больше чем на 20% от baseline.
- Path traversal: `../`, абсолютный путь, symlink — отказ.
- ZIP: имена без `..`, без абсолютных путей, без выхода за корень.
- Upload: лимит размера, расширения, пустой файл.
- Сеть: monkeypatch `socket.socket` → движок на демо не должен её трогать.
- Секреты: тест-сканер на `API_KEY`, `TOKEN`, `password` в диффе (простая регулярка).

## 12. Что не тестируем автоматически

- Вкус и композицию лендинга — гейт и владелец.
- Реальный корпус 44 989 пунктов — отдельный прогон `corpus`, не CI.
- Word→PDF на Ubuntu — нет Word; проверка на Windows вручную.
- Точные формулировки замечаний — только инварианты (категория, шифр, файл).
