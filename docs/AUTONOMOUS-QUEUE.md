# Автономная очередь (без дизайна)

Режим: брать issue по порядку, чинить, проверять тестами, коммитить по одному, комментировать
и переходить к следующему. **Дизайн не трогаем**: issue с метками `ui`, `landing`,
`accessibility` и задачи про лендинг/бренд/скриншоты пропускаем.

## Как это работает

- Ветка: `autonomous/YYYY-MM-DD` от свежего `main`; в `main` не пушим, в конце — draft PR.
- Один issue = один коммит с `(#N)`, тела коммитов из файлов (кириллица).
- После каждого issue: `pytest` затронутых тестов + `pytest -q` перед коммитом, если позволяют
  время и контекст.
- В issue — комментарий: что сделано, `файл:строка`, чем проверено. **Не закрываем** до мержа.
- Перед взятием: `assignees` пусты или `dettram`; чужие не берём.
- Синхронизация live-копии — только для проверки вручную, в коммит не идёт.

## Стоп-условия (остановиться и написать в issue/PR)

1. Тесты красные и не чинятся за ~15 минут.
2. Нужно решение владельца (оценка /10, приватность, доступ к файлам, публичность).
3. Безопасность: LAN/внешний доступ, auth, секреты, файловая система вне корня.
4. Конфликт с чужой веткой/незакоммиченной работой.
5. Три неудачные попытки подряд.
6. Контекст сессии заканчивается — остановиться на целом коммите, записать «следующий — #N».
