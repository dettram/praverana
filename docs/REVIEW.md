# Ревью кода

Две мысли взяты из [deslop-please](https://github.com/deterministic-machines/deslop-please)
(MIT, 22.11.2026). Это линтер для Rust: читает `cargo metadata`, Python не разбирает.
Поэтому берём принцип, а не инструмент; проверяется глазами в ревью.

## 1. Импорты без циклов и встречных слоёв

Направление зависимостей одно: `app/` → `scripts/` → стандартная библиотека.
`scripts/` не импортирует `app/`; нижний слой не знает о верхнем.

Нарушения:

- `a.py` импортирует `b.py`, а `b.py` — `a.py`, в том числе через третий модуль;
- `scripts/*` тянет `app/*`;
- цикл «разорван» импортом внутри функции — связь осталась, её просто не видно.

Что делать: общее вынести в нижний слой (`scripts/common.py`), а не прятать
импорт в функцию.

Как проверить: просмотреть `from`/`import` в затронутых файлах; в `scripts/`
не должно быть `from app` или `import app`.

## 2. Глубокий модуль, узкий интерфейс

Модуль прячет работу, а не пересылает её. Снаружи — вход и результат,
а не внутренние поля, глобалы и промежуточные структуры.

Нарушения:

- модуль-обёртка: одна функция, которая просто зовёт другую;
- чужой код правит поля объекта или читает глобалы модуля (`field-leak`);
- наружу выставлено всё, а не один-два входа.

Что делать: оставить один-два входа, остальное — `_приватное`; обёртку без
скрытой работы удалить и звать нижнюю функцию напрямую.

Как проверить: у нового модуля есть ответ «что он прячет». Если ответа нет —
это файл, а не модуль.

## Наши правила

Они важнее обоих пунктов выше:

- проверка детерминированная: без модели, сети и внешних API в рантайме
  (`docs/BRIEF.md:24`);
- замечание воспроизводимо: папка + файл + правило; новое правило — с тестом
  на `samples/demo-project` (`CONTRIBUTING.md:22–24`);
- пропуск файла, скана или страницы виден в отчёте, а не теряется молча.
