# Бриф для дизайн-помощников

## Продукт

**Праверана.by** — локальный аудит проектной документации по ТНПА Республики Беларусь.
Пользователь: инженер-проектировщик, ГИП, нормоконтроль, эксперт. Задача пользователя: быстро понять,
что в проекте противоречит нормам, и защитить отчёт.

Сегодня: папка проекта → список замечаний (шифр нормы, пункт, файл, страница) → отчёт DOCX/PDF →
размеченные копии DOCX с комментариями Word → история прогонов и сравнение «стало лучше».

## Что уже есть

- `app/` — движок проверок, отчёт, разметка, история, FastAPI-сервер, интерфейс `/app`, лендинг `/`.
- Лендинг собран на ките design-taste-frontend, гейт пройден: `GATE: PASS` (2 waiver, 8 WARN).
- Дизайн-токены: Onest + JetBrains Mono (локально), палитра из символики РБ
  (красный #C8102E, зелёный #23694A, золотой #8A5F14/#A97C22, бумага #FAF9F5, тушь #15181A).
- Знак: ромб с подрезанными концами, золотой ниткой и вырезанной галочкой; слоган —
  «Каждое замечание — с нормой, файлом и страницей».

## Ограничения

- Интерфейс и документы — на русском. Белорусские варианты допустимы как второй язык.
- Всё локально: без облака, аккаунтов и внешних API в рантайме.
- Нельзя: тексты норм, «инновационный/экосистема/решение под ключ», выдуманные цифры и отзывы.
- Нельзя менять код и файлы вне своей зоны: только свой документ в `docs/`.

## Что нужно от каждого

| Роль | Документ | Вопрос |
|---|---|---|
| lead | `docs/UX-BRIEF.md` | сценарии и экраны: что видит инженер от «взял папку» до «отдал отчёт», где теряется |
| copy | `docs/COPY.md` | слоган (3–5 вариантов), голос, терминология, микротексты кнопок и ошибок |
| system | `docs/SYSTEM.md` | токены и компоненты: что унифицировать, что нарушает канон, file:line |
| a11y | `docs/A11Y.md` | доступность лендинга и `/app`: клавиатура, контраст, цели, reduced motion |
| researcher | `docs/RESEARCH-UX.md` | как решают эту задачу другие (normativka, enp, tnpa, Bluebeam, PlanGrid и т. п.), с источниками и датой |

## Формат

- 1–2 страницы, конкретно, без общих слов.
- Каждое утверждение — либо из файла (`путь:строка`), либо с источником и датой.
- В конце — 5 приоритетных правок, которые дадут наибольший эффект.
- Не править код, не создавать другие файлы.
