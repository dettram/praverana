# Праверана.by — локальный интерфейс аудита

Папка проекта → список замечаний → отчёт DOCX/PDF и размеченные копии. Всё считается на машине
пользователя: файлы никуда не выгружаются, внешних сервисов нет.

Две страницы: `/` — лендинг продукта, `/app` — сам инструмент. Логотип — ромб (основа
белорусского орнамента) с галочкой; палитра — красный, зелёный, золотой и бумажный фон
(цвета государственной символики). Изображение Государственного герба не воспроизводится:
его использование регулируется законодательством и требует разрешения.

## Бренд и шрифты

Название — **Праверана.by** («проверено»). Знак — ромб с галочкой (основа рушникового орнамента),
палитра — красный `#C8102E`, зелёный `#23694A`, золотой `#8A5F14` (текст) / `#A97C22` (графика),
бумажный `#FAF9F5`, тушь `#15181A`. Цвета взяты из государственной символики; изображение герба
не воспроизводится.

Шрифты **локальные, @font-face** (`assets/fonts/fonts.css`, OFL): Onest (variable, 4 подмножества)
и JetBrains Mono (400/500). Внешних запросов к Google Fonts нет — проверка `font-load` проходит.

Лендинг собран на ките `design-taste-frontend` (system.css, layout.css, motion): секции ровно
в один экран, фиксированная шапка, единая сетка, момент `cursor-spotlight` в кадре героя.

Проверки (Node 22 в `%LOCALAPPDATA%\node22`):

```powershell
$env:PATH = "$env:LOCALAPPDATA\node22;$env:PATH"
$env:CHROME_PATH = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
cd app\ui

     --profile .taste-skill/chrome-check --page software --category "аудит проектной документации" `
     --primary "Проверить папку проекта"
node <skill>\scripts\gate.mjs --start "http://127.0.0.1:8765/" --kind software `
     --category "аудит проектной документации" --primary "Проверить папку проекта"

```

Состояние: **GATE: PASS** (2 waiver в `.taste-skill/waivers.json`, 8 WARN), copy-lint 0 FAIL,
consistency 0 FAIL на 1440, 390 и обходе 320. Waiver — только на `hero-lines` и `hero-maxchars`:
проверка подставляет 45 знаков вместо фактических 26 и считает строки для чужого заголовка.

Почта `hello@praverana.by` — домен нужно зарегистрировать; до этого адрес не принимает письма.

## Запуск

```powershell
cd "$env:USERPROFILE\.config\opencode\skill\stroy-calc-audit"
uv run --with fastapi --with uvicorn --with python-docx --with pypdf --with python-multipart `
    python app/server.py
```

Открыть <http://127.0.0.1:8765>. Остановить — `Ctrl+C` в консоли сервера.

CLI без интерфейса:

```powershell
uv run --with python-docx --with pypdf python app/engine.py --path "<папка>" --out result.json
```

## Что проверяется

| Категория | Проверка | Источник |
|---|---|---|
| нормы | шифр из текста → статус (отменён / заменён / не подтверждён) | `02-Реестр.csv`, `norm_check.classify` |
| цитаты | «шифр … п. X» → есть ли пункт, на какой странице | индекс `.stroy-audit/index.sqlite`, `clause.find_clause` |
| комплект | наличие ПЗ, АР, КР/КЖ/КМ, ИОС, ПОС, ППР, смет — по именам файлов | `engine.check_completeness` |
| ПОС/ППР | блоки приложений Г и В СН 1.03.04-2020 | `data/pos-ppr.json` |
| заглушки | «ХХХ», «___», «заполнить»; отдельно «по проекту» как инфо | регулярные выражения |

Свёртка: один шифр — одна строка со списком файлов и числом вхождений (иначе таблица тонет).
DOCX и PDF одного документа считаются одним источником.

## Что не проверяется (и об этом сказано в отчёте)

- Расчёты, армирование, нагрузки, сметы, пожарные решения — только человек.
- Чертежи DWG, модели RVT, сканы без OCR, XLSX.
- «Пункт не найден» = его нет в проиндексированных текстах, а не «пункт отменён».

## Оценка

10 баллов минус штрафы: −1,0 за ошибку (не более −6), −0,2 за предупреждение (−3),
−0,05 за инфо (−1). Оценка ниже 5 — «существенные дефекты», 5–8 — «требуются исправления»,
выше 8 — «пригодно к проверке».

## Отчёт

`report.py` собирает DOCX (Times New Roman, А4): титул, сводка с оценкой, **динамика с предыдущим
прогоном** (было/стало, исправленные и новые замечания), таблица замечаний, список прочитанных
документов, **разметка документов**, ограничения, порядок использования. PDF — экспорт Word через
COM (`to_pdf`), поэтому на машине должен быть установлен Word.

## Разметка документов

`markdoc.py` копирует DOCX и ставит на найденные места **комментарии Word** и подсветку:
ошибки — красным, предупреждения — жёлтым, инфо — бирюзовым. Ставится до трёх вхождений на шифр,
не более 80 на файл. В интерфейсе — кнопка «Разметка», отдаёт ZIP с размеченными копиями
(структура папок сохраняется). PDF не размечается: в нём остаются только строки отчёта.

Ограничения: разметка ищет точное вхождение текста в абзацах и таблицах DOCX; если шифр разорван
переносом строки или набран в другом регистре вразрядку — комментарий может не встать.

## История

Каждый прогон сохраняется в `~/.stroy-audit/audit-runs/<время>-<хеш папки>.json`.
Сравнение — по смыслу замечания (категория + норма + текст без счётчиков), поэтому перестановка
строк в отчёте не считается «новым замечанием».

В интерфейсе под сводкой: строка «Динамика с прогоном …» и список последних прогонов.
Если состав выборки изменился (например, включили .md/.txt), интерфейс и отчёт прямо пишут,
что сравнение по числу замечаний условное.

## Файлы

```
app/
  server.py       FastAPI: /api/audit, /api/upload, /api/report/{job}.docx|pdf, /api/marked/{job}.zip
  engine.py       движок проверок (CLI и импорт)
  report.py       DOCX + PDF (динамика, разметка)
  markdoc.py      комментарии Word и подсветка в копиях DOCX
  history.py      история прогонов и сравнение «стало лучше / хуже»
  ui/landing.html лендинг продукта (/)
  ui/index.html   инструмент (/app): путь или папка, сводка, динамика, фильтры, выгрузки
  ui/assets/      скриншоты продукта для лендинга
```

## Ограничения реализации

- Задачи живут в памяти процесса: после перезапуска сервера ссылки на отчёты пропадают.
- Загруженные через браузер файлы копируются во временную папку (`%TEMP%\stroy-audit-ui`).
- Одновременно обрабатывается один проект на задачу; тяжёлые папки (>600 файлов) обрезаются.
