# Протокол аудита (A–G), оценка и формат отчёта

Основано на `04-Аудиты/00-Обзор` (14 объектов, чек-лист, промпты, журнал оценок).

## Роли

| Роль | Что проверяет | Чем пользуется |
|---|---|---|
| **A. Норм-аудитор** | шифр существует, год верный, статус подтверждён, замена указана | `norm_check.py`, `02-Реестр.csv` |
| **B. Пожарный** | класс Ф, категория, степень огнестойкости, площадь отсека, приложение | СН 2.02.05-2020, СП 2.02.05-2026 |
| **C. Расчётчик** | все числа, формулы, единицы, внутренние противоречия | `numbers_ledger.py` |
| **D. Конструктор** | класс бетона, защитный слой, армирование, стали, сварка, болты, анкеры | `checks.py`, `checks-sp50301.md`, `checks-loads.md` |
| **E. Комплектность** | стадия, шифр, штампы, состав по СН 1.02.02-2023, PDF vs DWG | `06-Справочники/Оформление-чертежей` |
| **F. Факты/BIM** | совпадение отчёта с архивом/логом/IFC; нет утверждений без лога | листинги, `_логи`, IFC-CSV |
| **G. Методолог** | у каждой ошибки — пункт нормы или лист; нет «проверить»; вывод не добавляет фактов | этот файл |

Один прогон = один аудитор. Роли не смешиваются: B не пересчитывает армирование, C не судит нормы.

## Порядок

1. Зафиксировать объект, дату, состав файлов, что **не** читалось.
2. `norm_check.py` → блокеры по ссылкам.
3. `numbers_ledger.py` → реестр чисел и арифметика.
4. `search.py` по каждому спорному пункту → цитата `файл:страница`.
5. `checks.py` для классов бетона и армирования.
6. Отчёт по шаблону; оценка 0–10; журнал.

## Оценка

| Балл | Значение |
|---|---|
| 10 | ссылки и статусы верны, числа сходятся, каждое утверждение подтверждено |
| 8–9 | 1–2 некритичных замечания |
| 6–7 | один блокер или 3+ существенных |
| 3–5 | два и более блокеров |
| 0–2 | отчёт недостоверен |

«10» — только при отсутствии блокеров и подтверждённых ссылках. Вне базы РБ — отдельный статус, не 10.

## Шаблон отчёта

```
# Аудит проекта <шифр> — <объект>
Проверка по копии. Оригиналы не изменялись. Дата: <дд.мм.гггг>.
База: СН/СП/СТБ РБ, состояние на 18.11.2026.

## 1. Что проверено
комплект → файл(ы) → раздел → листы → изменение → объём

## 2. Сильные стороны
только видимое в файлах, с указанием файла/листа

## 3. Ошибки и недочёты
### 3.1. Нормативные ссылки
ссылка в проекте → где → проблема → действующая норма
### 3.2. Противоречия внутри проекта
«в АР — X, в КР — Y», без «вероятно»
### 3.3. Технические замечания
числа с единицами; где данных нет — «не проверено»

## 4. Оформление и комплектность
стадия | шифр | подписи | состав по СН 1.02.02-2023 | PDF vs DWG | титул/состав/содержание

## 5. Ограничения аудита
что не проверялось и почему

## 6. Сводная таблица «нарушение → норма → действие»

## 7. Вывод
3–5 пунктов из таблицы, без новых фактов и прогнозов
```

## Запрещено

- «соответствует действующей базе», если в таблице есть открытые пункты;
- один факт в плюсах и минусах;
- ссылка на норму без года или без источника статуса;
- «вероятно», «скорее всего», «обычно» в разделе ошибок;
- «проверить» в разделе ошибок — это «не проверено»;
- финальное «после исправления будет соответствовать».

## Повторная проверка

Оценка < 10 → правка → тот же аудитор проверяет заново. Итог — в журнал:
дата, версия, оценка, что закрыто, что осталось.
