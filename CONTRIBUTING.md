# Как участвовать

## Проблемы и задачи

Всё живёт в Issues. Шаблоны:

- **Bug** — что-то работает не так: проверка пропускает дефект, отчёт падает, разметка ломает файл.
- **Feature** — новая проверка, формат отчёта, улучшение интерфейса.
- **Norm gap** — норма есть в реестре, но нет текста; или шифр не опознан.

В обращении к норме указывайте **шифр, пункт и страницу** (`СН 1.03.04-2020, п. 7.7, с. 15`).
Без этого замечание нельзя проверить.

## Что не принимается

- Тексты ТНПА, отсканированные страницы норм, выдержки больше цитаты.
- Проектная документация заказчиков и любые персональные данные.
- «Улучшения» проверок, которые скрывают замечания вместо исправления правила.

## Правила для проверок

1. Любое замечание должно быть воспроизводимо: папка + файл + правило.
2. Новое правило — с тестом на демо-проекте (`samples/make_demo.py`).
3. Если правило нельзя сделать детерминированным — оно не становится проверкой,
   а становится задачей с пометкой «нужен человек».
4. Оценка не должна улучшаться за счёт удаления правил: формула меняется только с обоснованием.

## Локальная проверка перед PR

```powershell
uv run --with python-docx --with pypdf python app/engine.py --path samples/demo-project --out demo.json

# интерфейс
uv run --with fastapi --with uvicorn --with python-docx --with pypdf --with python-multipart `
    python app/server.py
```

Чек-лист ревью — `docs/REVIEW.md`: циклы импортов и модули-обёртки.

Для лендинга — гейты из `docs/LANDING.md` (нужен Node 22 и Chrome/Edge).
